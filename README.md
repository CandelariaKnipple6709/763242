# camswap — подмена камеры в iOS-браузере (веб-студия → WebRTC → WKWebView)

Инструмент для трансляций, где модератор прямо в браузере (без OBS и без
установки отдельных программ) загружает изображения — план сверху,
3D-модель, разбор этапов — редактирует их (масштаб, поворот, отражение,
позиция) и кликом переключает, какое из них сейчас «в эфире». Эта картинка
уходит на телефон и там подменяет реальную камеру в вашем стриминговом
сайте. Звук при этом остаётся настоящим — с микрофона телефона.

## Как это устроено

```
[Компьютер модератора]                    [Сервер]                [Телефон]
 Обычный браузер (Chrome/Edge)                                   iOS-приложение
 открывает http://ваш-сервер/                                    (WKWebView + camswap.js)
 (страница studio.html)
        │
        │ загрузка картинок, редактирование
        │ (масштаб/поворот/отражение/позиция),
        │ клик по превью — сцена сразу "в эфире"
        ▼
 canvas.captureStream() ── WebRTC video ──▶  signaling-server  ──▶  camswap.js получает
   (то, что видно на                            (Node.js,              видео-трек, рисует
    превью — то и уходит)                    WebSocket-relay,           его в свой canvas,
                                              только сигналинг:          подменяет
                                              SDP/ICE, без медиа)        navigator.mediaDevices
                                                                         .getUserMedia() на
                                                                         canvas.captureStream()
                                                                           │
                                                                           ▼
                                                               Ваш сайт в том же WKWebView
                                                               думает, что получил камеру
                                                               телефона — а на самом деле
                                                               получает картинку из студии.
                                                               Аудио остаётся настоящим
                                                               (микрофон телефона).
```

OBS и виртуальные камеры в этой схеме больше не участвуют. Единственная
программа, которую нужно ставить руками — сам сигнальный сервер (один раз,
на любом хостинге или локальной машине); всё остальное — веб-страница и
телефонное приложение.

Важно понимать: iOS/WKWebView не даёт официального API "подменить системную
камеру". Подмена делается на уровне JavaScript конкретной веб-страницы —
это надёжно работает для сайтов, которые получают видео через
`navigator.mediaDevices.getUserMedia()` (подавляющее большинство браузерных
стриминговых виджетов на WebRTC). Если у вашего сервиса есть проверки типа
`enumerateDevices()` с сверкой `label`/`deviceId` на сервере — их тоже можно
доработать (см. `ios-app/camswap.js`, там уже подменяется и `enumerateDevices`).

## Состав проекта

- `signaling-server/` — Node.js-сервер с двумя задачами:
  1. Раздаёт `public/studio.html` — ту самую веб-студию для модератора,
     просто как обычный сайт (`http://адрес-сервера/`).
  2. WebSocket-релей для WebRTC-сигналинга (SDP/ICE) между студией и
     телефоном. Само видео через сервер не идёт — только сигналинг.
- `signaling-server/public/studio.html` — страница модератора: загрузка
  картинок (drag&drop или кнопка), редактор (поворот, масштаб, отражение,
  перетаскивание мышью, зум колёсиком), список сцен-превью, подключение
  к комнате и старт вещания.
- `ios-app/` — исходники iOS-приложения (SwiftUI + WKWebView).
  `camswap.js` — читаемый исходник скрипта подмены камеры;
  `CamswapScript.swift` — его же содержимое, зашитое в код как
  base64-строка (именно этот файл реально попадает в сборку — так
  подмена не зависит от копирования отдельного ресурсного файла).
  `project.yml` — спецификация для XcodeGen (генерирует `.xcodeproj`
  без ручных кликов в Xcode; нужна для автосборки в п. «Сборка `.ipa`
  без Mac» ниже).
- `.github/workflows/build-ipa.yml` — сборка `.ipa` на бесплатном
  облачном Mac от GitHub Actions. Позволяет получить готовый файл для
  Sideloadly, вообще не имея собственного Mac (см. раздел ниже).
- `windows-studio/` — отдельное Windows-приложение (`.exe`) с тем же
  редактором сцен, что и в веб-студии, но: сигнальный сервер встроен
  прямо в приложение (не нужен отдельный `node server.js`), а вместо
  ручного ввода адреса/комнаты — QR-код на экране, который сканирует
  приложение на телефоне. См. раздел «Desktop-студия как `.exe`» ниже.
- `.github/workflows/build-windows-exe.yml` — сборка `windows-studio`
  в установочный `.exe` на бесплатном облачном Windows от GitHub Actions.

## ВАЖНОЕ ОГРАНИЧЕНИЕ ЭТОЙ СЕССИИ

Я работаю в облачном Linux-окружении без macOS/Xcode/iOS-устройства, поэтому
**не могу скомпилировать и живьём протестировать iOS-приложение** здесь.
Веб-часть (сервер + студия) я запустил и протестировал прямо в этой сессии:
раздача страницы, health-check и обмен SDP между "отправителем" и
"приёмником" через сигнальный сервер отработали корректно. iOS-код написан
аккуратно и синтаксически проверен, но финальную сборку и прогон на реальном
телефоне нужно сделать вам в Xcode на Mac — шаги ниже.

## Установка: сигнальный сервер + студия

```bash
cd signaling-server
npm install
PORT=8080 node server.js
```

Откройте `http://localhost:8080/` (или адрес сервера, если он не локальный) —
это и есть студия для модератора.

Для реального использования (не в одной локальной сети) разверните сервер
на любом хостинге с поддержкой WebSocket + TLS (Fly.io, Render, VPS и т.д.),
либо поставьте перед ним nginx/Caddy с `https://`/`wss://` — WKWebView не
станет соединяться по незащищённому `ws://` со страницы на `https://`, так
что для прод-использования TLS обязателен. Проверка живости: `GET /health`
→ `ok`.

### Быстрый вариант с TLS для тестов: ngrok

Поднимать полноценный хостинг с сертификатом не обязательно — для теста
(и вообще для съёмок из любой точки, не только по Wi-Fi с модератором)
удобно пробросить локальный сервер через [ngrok](https://ngrok.com/):

1. Установите ngrok, на компьютере модератора (там же, где `node server.js`)
   выполните:
   ```bash
   ngrok http 8080
   ```
2. Ngrok выдаст адрес вида `https://abcd1234.ngrok-free.app`.
3. В студии (поле «Signaling server») и в приложении на телефоне (поле
   «Signaling server» в настройках) впишите **этот же адрес, но с `wss://`
   вместо `https://`**: `wss://abcd1234.ngrok-free.app`.
4. Код комнаты — как обычно, одинаковый с обеих сторон.

Плюс этого способа: адрес уже защищён TLS (`wss://`), поэтому сайт,
загруженный по `https://`, не будет блокировать соединение как «смешанный
контент» — а именно так выглядит самая частая причина, по которой телефон
не может достучаться до студии. Плюс телефону больше не нужно быть в той
же Wi-Fi сети, что и компьютер модератора — ngrok сам маршрутизирует
трафик. У бесплатного ngrok адрес меняется при каждом перезапуске
туннеля — для регулярного использования стоит завести аккаунт с
постоянным поддоменом или в итоге переехать на нормальный хостинг с
собственным доменом.

## Использование: сторона модератора

1. Откройте `http://адрес-сервера/` в любом браузере на Windows (или где
   угодно) — установка не требуется.
2. Перетащите изображения в окно или нажмите «+ Добавить сцену» — план
   сверху, 3D-модель, скриншоты разбора этапов и т.д.
3. Первая загруженная картинка сразу становится «в эфире». Дальше — клик
   по превью сцены сразу переключает трансляцию на неё.
4. Для выбранной сцены доступны: повороты на 90° и произвольный угол
   (ползунок), отражение по горизонтали/вертикали, масштаб (ползунок или
   колесо мыши над превью), перетаскивание мышью для позиционирования,
   кнопка «Сбросить».
5. Укажите код комнаты (любая строка, тот же код нужно будет ввести в
   приложении на телефоне) и нажмите «Начать вещание». Поле адреса сервера
   уже подставлено автоматически (совпадает со страницей).

## Использование: сторона телефона (iOS-приложение)

Интерфейс — как в обычном мобильном браузере: внизу экрана постоянная
адресная строка (ввели адрес → «Перейти»/Go на клавиатуре), сверху —
кнопки «назад», «обновить» и статус подмены камеры.

1. Если используете **desktop-студию (`.exe`)** — просто нажмите значок
   QR-кода сверху и наведите камеру на код на экране компьютера, всё
   остальное заполнится и подключится само (см. раздел «Desktop-студия
   как `.exe`» ниже). Если используете веб-студию — нажмите шестерёнку
   и один раз укажите: тот же адрес сигнального сервера (`wss://...`) и
   тот же код комнаты, что и в студии → «Применить».
2. В адресной строке внизу введите адрес вашего стримингового сайта и
   нажмите «Перейти» — дальше это обычная адресная строка браузера, можно
   переходить на другие страницы того же сайта как угодно.
3. Когда сайт запросит камеру (обычно кнопка «начать трансляцию»), вместо
   реальной камеры он получит то, что сейчас выведено «в эфир» в студии.
   Микрофон — настоящий, с телефона.

Внизу экрана (если включён статус-бейдж в настройках) появляется
маленькая подсказка вида «camswap: видео получено» — по ней удобно
проверять, что подмена и WebRTC-соединение реально работают, ещё до
захода на сайт.

## Desktop-студия как `.exe`

Отдельное Windows-приложение вместо веб-студии в браузере. Тот же редактор
сцен (загрузка картинок, поворот/масштаб/отражение/позиция, клик — сразу
в эфир), но с двумя отличиями:

- Сигнальный сервер встроен прямо в `.exe` — отдельно запускать
  `node server.js` не нужно, при старте приложения сервер поднимается
  сам.
- Вместо ручного ввода адреса сервера и кода комнаты на экране
  показывается QR-код. Приложение генерирует случайный код комнаты
  при каждом запуске и сразу же готово ждать подключение — ничего
  нажимать не нужно, кроме как отсканировать код на телефоне.

### Сборка `.exe`

Как и с `.ipa`, собрать `.exe` можно бесплатно на GitHub, без установки
чего-либо на свой компьютер:

1. Загрузите (или обновите, если уже загружали проект) папку
   `windows-studio` и файл `.github/workflows/build-windows-exe.yml` в
   тот же репозиторий, куда загружали остальной проект.
2. Вкладка **Actions → Build Windows .exe → Run workflow**.
3. Дождитесь **Success** (сборка на Windows обычно быстрее, чем на
   Mac — пары минут достаточно), откройте завершённый запуск, скачайте
   артефакт **CamSwapStudio-installer**.
4. Внутри — установочный `.exe`. Запустите его на компьютере модератора,
   пройдите обычную установку.

### Использование

1. Запустите **CamSwap Studio**. Приложение сразу поднимает свой сервер
   и показывает QR-код с кодом комнаты справа от рабочей области —
   никаких дополнительных действий на этом этапе не требуется.
2. На телефоне в приложении нажмите значок QR-кода (сверху рядом с
   шестерёнкой) и наведите камеру на код на экране компьютера. Сервер и
   комната подставятся и применятся автоматически.
3. Дальше — как в веб-студии: перетаскивайте картинки, редактируйте,
   кликайте по превью, чтобы переключить, что «в эфире».
4. Если нужна трансляция **не по локальной сети** (телефон и компьютер
   в разных местах) — раскройте «Расширенные настройки» в приложении,
   впишите публичный адрес (`wss://...ngrok-free.app` или адрес вашего
   постоянного хостинга, см. раздел про ngrok выше) и нажмите «Применить
   и переподключить». QR-код при этом продолжит показывать локальный
   адрес — в этом случае код придётся отсканировать на телефоне, а
   затем в настройках телефона вручную поправить адрес сервера на тот
   же публичный, что вписали в приложении.
5. Кнопка «Новый код» генерирует свежий код комнаты и новый QR (например,
   если хотите начать всё заново или комната случайно занята).

Важно: телефон и компьютер должны быть в одной Wi-Fi сети, если
пользуетесь QR-кодом «как есть» (без расширенных настроек) — QR
кодирует локальный IP-адрес компьютера, а он недоступен извне домашней
сети.

## Сборка `.ipa` без Mac (полностью на Windows, через GitHub Actions + Sideloadly)

Если Mac нет вообще, `.ipa` можно собрать бесплатно в облаке и поставить
на телефон через Sideloadly, ни разу не открыв Xcode самому.

1. **Зарегистрируйте GitHub-аккаунт** (бесплатно, github.com) и создайте
   новый репозиторий — можно **публичный** (тогда сборка бесплатна и без
   лимитов) или приватный (тогда расходует ваши бесплатные минуты Actions,
   macOS-раннеры считаются с коэффициентом ×10).
2. **Загрузите содержимое папки `camswap`** в этот репозиторий целиком —
   на странице репозитория **Add file → Upload files**, перетащите туда
   все папки (`ios-app`, `.github`, `signaling-server`, `README.md`).
   GitHub позволяет перетащить целую структуру папок прямо в браузере,
   git через командную строку не нужен.
3. Откройте вкладку **Actions** репозитория. Если появится баннер про
   включение Actions — подтвердите (**I understand my workflows, go
   ahead and enable them**).
4. Слева выберите workflow **Build iOS .ipa**, справа нажмите
   **Run workflow → Run workflow** (ветка `main`/`master`).
5. Дождитесь зелёной галочки (обычно 3–7 минут — идёт сборка на
   виртуальном Mac). Откройте завершённый запуск, внизу страницы будет
   раздел **Artifacts** с файлом `CamSwap-ipa`.
6. Скачайте его — это zip-архив, внутри лежит `CamSwap.ipa`. Именно его
   и перетаскивайте в Sideloadly (шаг 4 из инструкции по установке выше).
7. Если сборка упадёт с ошибкой — откройте лог упавшего шага (клик по
   шагу разворачивает вывод) и пришлите мне текст ошибки, поправим
   `project.yml` или workflow под конкретную причину.

Этот путь даёт **неподписанный** `.ipa` — это нормально и ожидаемо:
Sideloadly сам подписывает приложение вашим Apple ID в момент установки
на телефон, поэтому готовый сертификат разработчика в файле не нужен.

## Сборка iOS-приложения в Xcode (если Mac всё же есть)

1. Xcode → **File → New → Project → iOS → App**.
   - Product Name: `CamSwap` (или любое)
   - Interface: **SwiftUI**
   - Language: **Swift**
2. Удалите автосгенерированные `ContentView.swift` и `<Имя>App.swift`,
   вместо них добавьте (Drag & Drop в навигатор проекта, отметить
   "Copy items if needed" и ваш app target):
   - `CamSwapApp.swift`
   - `ContentView.swift`
   - `WebViewStore.swift`
   - `WebViewRepresentable.swift`
   - `CamswapScript.swift`
   - `QRScannerView.swift`

   `camswap.js` в проект добавлять не нужно — его содержимое уже зашито
   в `CamswapScript.swift` в виде base64-строки (так надёжнее: не зависит
   от того, попадёт ли отдельный ресурсный файл в бандл при сборке).
   Файл `camswap.js` в репозитории остаётся как читаемый исходник для
   правок; если его меняете, перегенерируйте `CamswapScript.swift`
   командой `base64 -w0 camswap.js` и вставьте новую строку.
3. В `Info` таргета добавьте два ключа:
   - **Privacy - Microphone Usage Description** (`NSMicrophoneUsageDescription`)
     — строка вроде "Микрофон нужен для передачи звука во время трансляции".
     Нужен, потому что аудио берётся с настоящего микрофона.
   - **Privacy - Camera Usage Description** (`NSCameraUsageDescription`) —
     строка вроде "Камера нужна для сканирования QR-кода подключения к
     студии на компьютере". Нужен для кнопки сканирования QR-кода
     (это единственное место, где приложение использует настоящую
     камеру, — сама подмена в браузере системную камеру не запрашивает).
4. Подключите iPhone, выберите его как Destination, укажите свою команду
   подписи (Signing & Capabilities → Team; для личного тестирования
   достаточно бесплатного Apple ID) → **Run**.
5. При первом запуске на реальном устройстве нужно один раз подтвердить
   доверие разработчику: **Настройки → Основные → VPN и управление
   устройством**.

## Проверка перед эфиром (чек-лист)

- [ ] `node signaling-server/server.js` запущен и доступен по `https://`/
      `wss://` и с телефона, и с компьютера модератора (не только localhost).
- [ ] В студии загружены нужные сцены, первая проверка переключения между
      ними сделана.
- [ ] В студии статус показывает «Трансляция активна» (зелёным) после
      подключения телефона.
- [ ] В приложении на телефоне статус-бейдж внизу экрана показывает
      «видео получено» (зелёным) — подмена уже активна ещё до захода на сайт.
- [ ] На сайте, при старте трансляции, в превью видно картинку из студии,
      а не реальную камеру телефона.
- [ ] Звук идёт с телефона (скажите что-нибудь и проверьте по превью/
      мониторингу на стороне сервиса).

## Известные ограничения MVP

- Один-к-одному: одна комната = одна студия и один телефон-приёмник. Для
  нескольких одновременных трансляций — свои комнаты (разные вкладки
  студии + разные коды).
- Сцены живут только в памяти открытой вкладки браузера — при перезагрузке
  страницы их нужно будет загрузить заново. Если нужно сохранение между
  сессиями, можно добавить сохранение в файл/localStorage — скажите, если
  актуально.
- Сайт получает фиксированное разрешение канвы (1280×720@30 fps) независимо
  от того, что он просит через constraints — обычно этого достаточно.
- Без TURN-сервера соединение может не устанавливаться в сетях со строгим
  NAT/файрволом (мобильный интернет иногда капризничает). Для надёжности
  на реальных эфирах стоит добавить TURN (например, через coturn или
  managed-сервис) в `iceServers` в обоих местах (`studio.html` и
  `camswap.js`).
- `enumerateDevices()` подменяется только на один фейковый видео-вход;
  если у вашего сайта сложная логика выбора камеры (несколько реальных
  камер в списке), может понадобиться доработка.
